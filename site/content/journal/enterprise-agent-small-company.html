You type a question. You get an answer. Then it waits.

That is most AI today. It is a cookbook: full of good answers, and no use at all until somebody opens it.

What most businesses want is a pair of hands. Someone in the kitchen whether you are there or not, watching the mailbox, drafting the reply, flagging the problem, suggesting what to do next.

OpenClaw is the project that, in my view, put a pair of hands in everyone’s kitchen. It wasn’t the first piece of software to be called an agent. An agent is simply an AI assistant that can take actions and keep going, instead of only answering a question. But OpenClaw showed a wide audience that one could live on your own machine, inside the apps you already use, and work without waiting for the next prompt.

To me, it is the agent that started the others.

A weekend project

Peter Steinberger started it over a weekend in November 2025. It began as a WhatsApp assistant, went through a few names, and landed as OpenClaw at the end of January 2026.

In February 2026 Steinberger joined OpenAI, and OpenClaw moved to an independent foundation that OpenAI sponsors. Keep that in mind whenever OpenAI is the one describing it, including below.

OpenAI later described a persistent agent as one that can run all day and take action without being asked each time. Steinberger still says OpenClaw works best on a computer that stays on.

That is the shift I care about. You stop treating AI as a clever search box. You start treating it as a junior in the kitchen: someone who needs a clear job, some limits, and a person to taste the work before it goes out.

Why I’d still choose it

If you want a workflow shaped entirely around your business, with any model you like, I still think OpenClaw is the best option. Especially if you want a local model.

A local model is an AI model that runs on a computer you control, instead of being sent out to a company in the cloud. OpenClaw can use either, and you can mix them: a stronger cloud model for the hard work, a cheaper or local one for routine drafts.

It is also self-hosted. You install and run it on machines you own or rent. Your machines, your rules, your choice of model.

It has never been easier to start

Nine months ago, getting started meant a terminal window and some patience. A native app is now part of the official way in.

Windows got an installer in June. The Mac got ordinary, click-through setup in September. You download it, click through, and have a working assistant. No terminal.

Apps for iPhone and Android arrived in June as well. Think of them as a remote control for an agent that runs on your computer.

The hard part is no longer the install. It is deciding what the job is.

Several agents, one small machine

One OpenClaw Gateway can run several isolated agents, each with its own workspace, memory and job.

If the models stay in the cloud, the machine can be modest. Official guidance is that even a small always-on board, such as a Raspberry Pi, can run the Gateway. A local model needs a more capable computer, and you should test the quality on real work before you rely on it.

The machine won’t be the limit. The number of jobs you can describe clearly will be.

The rules on the kitchen wall

Here is why a lot of companies still ban tools like this. An assistant that can post, pay or change a record needs stronger rules than a chat window does.

That is the gap OpenClaw Enterprise is trying to close. It launched on 29 September 2026 as a free, self-hosted control plane for persistent agents. In plain terms, a control plane is the rota and the rules on the kitchen wall: who works here, what each of them may touch, and who signs off.

It started inside OpenAI, was donated to the OpenClaw Foundation, and is being developed with Red Hat and Nvidia. You run it on your own servers. The software is free. You pay for the machines and any cloud models.

The security features are the point:

  • a fence around what the agent can reach
  • permissions
  • a second model that can review actions
  • an audit trail

OpenAI and Red Hat are running internal pilots. On 12 November, OpenAI published how it uses those kinds of controls internally.

Now the honest part. This is still pre-1.0. It is officially for internal pilots only, with version 1.0 planned for later this year. Some security pieces are still being built. I would not put it on customer-facing work yet, and you will still need someone technical.

There is a second honest part, and it applies to every version of OpenClaw. Agents can install add-ons, called skills, from a public marketplace called ClawHub. In February, researchers found 341 malicious skills among the 2,857 they checked. Scanning has been added since, and a few still got through.

Treat a skill like an ingredient from a supplier you have never used. Check where it came from before it goes in the pot. Better still, start with none.

Even so, I think OpenClaw Enterprise could become the first widely usable, self-hosted enterprise agent that a smaller company can consider.

Four ways in

1. Stay with a hosted business plan. ChatGPT, Claude or Grok Bot on a Team, Business or Enterprise plan. Best if you want a capable assistant quickly, with little IT work. The cost is a monthly subscription. The trade-off is less control over the model and the workflow.

2. Run OpenClaw yourself, with cloud models. Install the official app on an always-on machine and start with one agent, or a few. Best for a small team that wants a custom workflow and a mix of models. The software is free. You pay for the machine and the model usage, and you manage keys, updates and access.

3. Run OpenClaw with a local model. Same software, but the model runs on your hardware. Best for work you don’t want leaving the building, or if you are watching AI bills. You need a stronger machine, and you need to have tested the quality.

4. Pilot OpenClaw Enterprise. Best once you have a useful agent and need permissions, isolation and an audit trail. The software is free, but you will need technical help. Treat it as a trial on internal work. It isn’t a finished platform yet.

A hybrid is fine: a hosted plan for everyday questions, and a self-hosted agent for work that needs a custom workflow or a tighter boundary.

Thirty days

  • Week 1. Pick one internal job. Only one. Write a short brief, including what the agent must never do. Use a hosted plan if it already covers the job, or install OpenClaw on a computer that stays on. Install no add-on skills yet.
  • Week 2. Run one agent on that task. A person reviews every send, every spend and every change to a record. Set a spending limit on any cloud model key.
  • Week 3. If the work is good enough, add a second agent for a different job, or try a cheaper or local model for the routine part.
  • Week 4. Only if you need shared permissions and an audit trail, start an OpenClaw Enterprise pilot on the same internal workload. Keep it away from customers. Then decide whether to keep it, stay with self-hosted OpenClaw, or go back to a hosted plan.

Before you leave the kitchen

A cookbook never burnt anything. A pair of hands can.

That is the price of having someone in the kitchen who acts without being asked. It is why the brief, the fence and the human check matter more than which model you choose.

OpenClaw is still, in my view, the most flexible way to build a workflow around the model of your choosing. It is easier to start than it has ever been. Several agents can share one small machine. And a careful Enterprise pilot is a realistic way to add the rules.
