My own assistant runs on OpenClaw. It can see my email, my diary and my files. It isn’t perfect. I’d still pick it.

You type a question. You get an answer. Then it sits there and waits.

That’s most AI today. A cookbook. Full of good answers, and no use until somebody opens it.

What most businesses actually want is a pair of hands. Someone in the kitchen whether you’re there or not, watching the inbox, drafting the reply, flagging the problem, suggesting what to do next.

OpenClaw is the project that, to me, put a pair of hands in everyone’s kitchen. It wasn’t the first thing to be called an agent. An agent is just an AI assistant that can take actions and keep going, instead of only answering. But OpenClaw showed a lot of people that one could live on their own machine, inside the apps they already use, and get on with things without being asked.

I think of it as the agent that started the others. You can argue with that. I’d still say it.

A weekend project

Peter Steinberger started it over a weekend in November 2025. It began as a WhatsApp assistant, went through a few names, and landed as OpenClaw at the end of January 2026.

In February 2026 Steinberger joined OpenAI, and OpenClaw moved to an independent foundation that OpenAI sponsors. Bear that in mind whenever OpenAI is the one describing it, including further down.

OpenAI later described a persistent agent as one that can run all day and act without being asked each time. Steinberger still says OpenClaw works best on a computer that stays on.

That’s the shift I care about. You stop treating AI like a clever search box. You start treating it like a junior in the kitchen. Someone who needs a clear job, some limits, and a person to taste the work before it goes out.

Why I’d still pick it

If you want a workflow built entirely around your business, with any model you like, I still think OpenClaw is the best option. Especially if you want a local model.

There are others. Hermes Agent is safer out of the box, and NanoClaw is small enough to read every line of. I’d still pick OpenClaw for how far you can bend it.

A local model is an AI that runs on a computer you control, instead of being sent off to a company in the cloud. OpenClaw can use either, and you can mix them. A stronger cloud model for the hard work, a cheaper or local one for routine drafts.

It’s also self-hosted. You install it and run it on machines you own or rent. Your machines, your rules, your choice of model.

This is where it gets interesting for customer data. Pulling records together, cleaning them, finding the duplicates, checking an address against a postcode. Dull, valuable work, and work you might not want on anyone else’s servers.

With a local model, the thinking happens on your machine. Set it up with no cloud backup, no chat app in the middle and no web tools, and the data’s got no reason to leave the building.

That takes setting up on purpose, though. OpenClaw’s own guidance is to keep a cloud model as a backup, and a backup will send your data out the moment the local model falls over. So for this job, turn it off, use a machine you own, and give the agent a copy of the data, not the original. The data protection rules still apply. Keeping it local just makes them easier to meet.

It’s never been easier to start

Nine months ago, getting going meant a terminal window and a lot of patience. A native app is now part of the official way in.

Windows got an installer in June. The Mac got normal, click-through setup in September. Download it, click through, and you’ve got a working assistant. No terminal.

Apps for iPhone and Android landed in June too. Think of them as a remote control for an agent that runs on your computer.

The install isn’t the hard part any more. Deciding what the job is, that’s the hard part.

Several agents, one small machine

One OpenClaw Gateway can run several separate agents, each with its own workspace, memory and job.

If the models stay in the cloud, the machine can be modest. The official guidance is that even a little always-on board, like a Raspberry Pi, can run the Gateway. A local model needs a properly capable computer, and you should test it on real work before you rely on it.

The machine won’t be what holds you back. The number of jobs you can describe clearly will be.

The rules on the kitchen wall

This is why plenty of companies still ban tools like this. An assistant that can post, pay or change a record needs stronger rules than a chat window does.

That’s the gap OpenClaw Enterprise is trying to close. It launched on 29 September 2026 as a free, self-hosted control plane for persistent agents. In plain terms, a control plane is the rota and the rules on the kitchen wall. Who works here, what each of them can touch, and who signs off.

It started inside OpenAI, was donated to the OpenClaw Foundation, and is being built with Red Hat and Nvidia. You run it on your own servers. The software’s free. You pay for the machines and any cloud models.

The security features are the whole point:

  • a fence round what the agent can reach
  • permissions
  • a second model that can check its actions
  • an audit trail

OpenAI and Red Hat are running internal pilots. On 12 November, OpenAI published how it uses those kinds of controls internally.

Now the honest bit. It’s still pre-1.0. It’s officially for internal pilots only, with 1.0 planned for later this year. Some of the security pieces are still being built. I wouldn’t put it on anything customer-facing yet, and you’ll still need someone technical.

There’s a second honest bit, and it applies to every version of OpenClaw. Agents can install add-ons, called skills, from a public marketplace called ClawHub. In February, researchers found 341 malicious skills among the 2,857 they checked. Scanning’s been added since, and a few still got through.

Treat a skill like an ingredient from a supplier you’ve never used. Check where it came from before it goes in the pot. Better still, start with none.

Even so, I think OpenClaw Enterprise could become the first properly usable, self-hosted enterprise agent a smaller company can actually consider.

Four ways in

1. Stick with a hosted business plan. ChatGPT, Claude or Grok Bot on a Team, Business or Enterprise plan. Best if you want something capable quickly, without much IT work. It costs a monthly subscription. You get less control over the model and the workflow.

2. Run OpenClaw yourself, with cloud models. Put the official app on a machine that stays on and start with one agent, or a few. Best for a small team that wants its own workflow and a mix of models. The software’s free. You pay for the machine and the model usage, and you look after the keys, updates and access.

3. Run OpenClaw with a local model. Same software, but the model runs on your own hardware. Best for work you don’t want leaving the building, or if you’re watching the AI bill. You’ll need a stronger machine, and you’ll need to have tested the quality.

4. Pilot OpenClaw Enterprise. Best once you’ve got an agent that’s useful and you need permissions, separation and an audit trail. The software’s free, but you’ll need technical help. Treat it as a trial on internal work. It isn’t finished.

Mixing them is fine. A hosted plan for everyday questions, and a self-hosted agent for the work that needs its own workflow or a tighter boundary.

Thirty days

  • Week 1. Pick one internal job. Just one. Write a short brief, including what the agent must never do. Use a hosted plan if it already covers the job, or put OpenClaw on a computer that stays on. No add-on skills yet.
  • Week 2. Run one agent on that job. A person checks every send, every spend and every change to a record. Put a spending limit on any cloud model key.
  • Week 3. If the work’s good enough, add a second agent for a different job, or try a cheaper or local model for the routine bit.
  • Week 4. Only if you need shared permissions and an audit trail, start an OpenClaw Enterprise pilot on the same internal work. Keep it away from customers. Then decide: keep it, stay with plain OpenClaw, or go back to a hosted plan.

Before you leave the kitchen

A cookbook never burnt anything. A pair of hands can.

That’s the price of having someone in the kitchen who acts without being asked. It’s why the brief, the fence and the person checking matter more than which model you pick.

OpenClaw is still, to me, the most flexible way to build a workflow round the model you choose. It’s easier to start than it’s ever been. Several agents can share one small machine. And a careful Enterprise pilot is a realistic way to add the rules.
